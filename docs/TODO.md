### 有新版本时的提醒标签

> 2026-10-29 提出。需求：新版本发布后，在页面上显示“有新版本”标签。
> 现状记录：目前页面上会出现“配置来自更高版本，无法安全读取。已备份为 config.json.future-v12-<时间戳>.json 并恢复默认设置。”，需要先分清这是版本标签需求，还是更新流程里的降级读取问题。

- [ ] 新增“有新版本”标签：确定出现条件（检测到更高版本、还是下载完成后）、显示位置（关于页 / 顶部导航旁 / 托盘）以及点击后的行为。
- [ ] 核实“配置来自更高版本，无法安全读取”文案的产生场景：是用低版本打开高版本写过的配置时的预期保护，还是升级流程中的数据处理问题；若是前者的正常保护，需要给用户更易懂的说明与恢复指引。

### 更新公告弹窗

> 2026-10-29 提出。需求：新增“更新公告”功能，页面入口放在“关于”里；每次更新后自动弹窗展示；内容尽量简洁，只讲业务功能变化，不写技术实现细节；最新版本始终排在最顶部。

- [ ] 关于页新增“更新公告”入口，可查看历史版本的更新内容。
- [ ] 更新后首次启动自动弹窗，只展示本次版本的内容；需要确定“更新后”的判定方式（例如记录上次运行的版本号）以及弹窗的关闭 / 不再提示行为。
- [ ] 公告列表按版本倒序排列，最新版本在最顶部；每条只写用户能感知的功能变化。
- [ ] 待确认：公告内容随包内置还是从 Release 拉取，以及是否需要“查看全部更新”和“知道了”两个动作。

### 滚动条样式优化

> 2026-10-29 提出。现状：设置页内容区、弹窗正文与桌宠形象条只用了 `scrollbar-width: thin`，颜色和圆角完全跟随系统；气泡与快捷菜单的滚动条被隐藏。没有统一的滚动条样式规则。

- [ ] 确定统一方案：自定义颜色 / 圆角 / 宽度，还是保持系统细滚动条、只统一各区域的显示与隐藏行为。
- [ ] 待确认：覆盖范围（设置内容区、弹窗正文、形象条、备忘正文与卡片），以及是否需要悬停时才显现。

> 2026-10-20 本轮暂缓：不购买证书、不提交申请、不使用自签名冒充已签名；优先评估 SignPath Foundation / Certum 开源签名资格（见 OPEN_ITEMS）。

- [ ] 调研 Windows 安装包与可执行文件的代码签名方案和可行性。
- [ ] 待确认：证书类型（OV/EV）、获取与续费成本、身份验证周期、签名工具与时间戳服务、CI 中安全保存证书和密码、签名后 SmartScreen 信誉，以及是否同时签安装版、便携版和卸载程序。

### 模块设置页与功能管理的启用开关重复

> 2026-10-29 暂缓：这项需求还没有考虑清楚（启用/停用到底应该只保留在一处，还是设置页也允许原地切换），先不实施。改造会移除 DeepSeek / ESA 设置页右上角的启用开关，并顺带修掉“在模块设置页停用后自动跳回常规”的导航异常。

- [ ] 决定启用/停用只保留在功能管理页，还是模块设置页保留只读状态 + 跳转链接。
- [ ] 若移除开关，确认模块设置页头部只保留“← 功能管理 / 前往功能页”是否足够，以及从功能页齿轮进入的用户是否仍需原地停用。
