# 阶段 B：视图懒加载与 CSS 按需加载结果

> 完成日期：2026-10-17
> 对比基线：[docs/performance-baseline.md](performance-baseline.md)（代码版本 `a782e0a`）
> 测量环境：与基线相同的 Windows 11、Ryzen 7 8845H、Node 22.22.2、Electron 44.8.0

## 1. 实施内容

- 只将设置页改为 `React.lazy(() => import('./settings/SettingsApp'))`，其余三个视图保持静态导入。
- `main.tsx` 只保留 `tokens.css`、`base.css`、`components.css` 三个公共样式；`settings.css` 随设置页 chunk 加载。
- 宠物、菜单、气泡组件分别导入自己的样式，但因为没有动态导入，这些样式仍会合并进入口 CSS。
- 未修改窗口路由方式、IPC、业务逻辑、设计 token 或任何用户可见行为。

### 1.1 为什么不是四个视图全部懒加载

先按报告建议实现了四个视图全部懒加载，并实测到三个问题：

| 变体                   | 冷启动宠物内容挂载中位数 | 菜单打开到内容挂载中位数 | 气泡首次动作                   |
| ---------------------- | -----------------------: | -----------------------: | ------------------------------ |
| 基线（无分割）         |                  1182 ms |                   254 ms | 正常显示                       |
| 四视图全部懒加载       |       1476 ms（+294 ms） |        486 ms（+232 ms） | 首次动作丢失 payload，气泡空白 |
| 仅设置页懒加载（最终） |                  1204 ms |                   257 ms | 正常显示                       |

结论：在当前 Electron `file://` 生产环境下，每个动态 chunk 首次加载约有 200–300 ms 的额外延迟；气泡窗口还会因为 payload 在监听器注册前到达而丢失首次内容。这些是功能或体验回退，不能作为优化保留。设置页体积大、打开频率低、且没有推送式初始 payload，适合作为唯一的懒加载边界。

## 4. 启动与窗口打开耗时

### 4.1 启动

| 指标               | 基线中位数 | 阶段 B 中位数 |               变化 |
| ------------------ | ---------: | ------------: | -----------------: |
| 冷启动窗口可见     |    1600 ms |       1491 ms |            -109 ms |
| 热启动窗口可见     |    1565 ms |       1343 ms |            -222 ms |
| 冷启动宠物内容挂载 |    1182 ms |       1204 ms | +22 ms（波动范围） |

窗口可见时间受启动波动影响较大（阶段 B 冷启动三次为 1331/1491/1592 ms），不能单独作为宠物更早出现的证据。宠物内容挂载与基线基本持平，说明没有可感知的启动收益，也没有实质退步。

### 4.2 菜单与设置

| 操作                        | 基线中位数 | 阶段 B 中位数 |    变化 |
| --------------------------- | ---------: | ------------: | ------: |
| 打开快捷菜单 → 菜单内容挂载 |     254 ms |        257 ms |   +3 ms |
| 点击设置 → 设置内容挂载     |     226 ms |        483 ms | +257 ms |

设置页首次打开会多等待一次 chunk 加载；这是把设置代码从常驻加载中移出的直接代价。菜单和各常驻窗口不受影响。

## 7. 结论与限制

- 达到阶段 B 的核心目标：宠物、菜单、气泡不再加载设置页的约 30 KB JS 与 5.2 KB CSS，加载边界由生产构建实测确认。
- 没有为了“四个都懒加载”而保留实测到的启动、菜单延迟和气泡首次 payload 丢失问题；最终只对设置页做按需加载。
- 设置页首次打开增加约 257 ms，属于已知取舍；如果后续要求更快，可在菜单打开后做空闲预取，但本阶段不引入该复杂度。
- 未在安装版/便携版中逐窗口点击验收；本阶段验证针对 `win-unpacked` 生产构建。
- 冷启动窗口可见时间波动较大，后续比较应继续以“宠物内容挂载”为主指标。
